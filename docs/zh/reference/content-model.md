# 内容模型

为了让 wiki 内容长期可维护，建议按文档类型来组织，而不是只按人员或临时项目分类。

## 推荐页面类型

### Guide

操作型内容，强调步骤、流程和上手路径。

示例：

- 快速开始
- 环境搭建
- 发布流程

### Reference

说明型内容，强调稳定性和可引用性。

示例：

- 架构说明
- 字段定义
- 配置说明

### FAQ

高频问题集合，强调快速定位答案。

### Changelog

面向团队同步变化，帮助读者了解最近新增或调整的内容。

## 命名建议

- 目录名称保持语义稳定，如 `guide`、`reference`
- 页面文件名尽量使用英文短语并采用中划线分隔
- 页面标题面向读者表达，文件名面向维护者表达

## 何时拆分页面

出现下面情况时，建议从一个长页面拆成多个子页面：

- 单页内容过长，查找成本明显升高
- 一个页面混合了“背景说明”和“操作步骤”
- 不同读者群体只关心其中一部分内容
