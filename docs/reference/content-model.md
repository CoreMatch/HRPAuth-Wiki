# Content Model

To keep the wiki maintainable over time, organize content by document type rather than by person or short-lived project.

## Recommended Page Types

### Guide

Task-oriented content focused on steps, workflows, and onboarding paths.

Examples:

- quick start
- environment setup
- release process

### Reference

Explanatory content focused on stability and long-term reuse.

Examples:

- architecture notes
- field definitions
- configuration references

### FAQ

A collection of recurring questions designed for quick lookup.

### Changelog

A running record of changes that helps the team stay aware of new or updated content.

## Naming Suggestions

- Keep directory names semantically stable, such as `guide` and `reference`
- Prefer English slugs with kebab-case file names
- Let page titles speak to readers and file names speak to maintainers

## When to Split a Page

It is usually time to break one long page into multiple pages when:

- the page becomes difficult to scan
- background explanation and task steps are mixed together
- different audiences only care about different parts of the content
