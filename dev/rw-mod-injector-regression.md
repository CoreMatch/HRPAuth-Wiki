# 回归脚本

一条命令拉起一套完整的真环境——真游戏客户端、真服务端——端到端跑模组装配链路，包括对误报敏感的失败断言。脚本位于 RW-Mod-Injector 仓的 `scripts/regress-e2e.sh`。

```bash
bash scripts/regress-e2e.sh
```

## 拉起什么

- **真游戏客户端**，并安装本仓的注入器
- **两个真 Avalon 实例**，从本地检出构建：一个零模组大厅、一个模组房
- **一个真 Cascade** 代理，使用全新配置与全新签名密钥

全部运行在临时目录中。Avalon 与 Cascade 的检出只读使用（只构建、不修改），不触碰任何既有实例与配置。客户端原态（模组目录、偏好设置、注入器文件）先备份，结束时必定还原——即使运行失败或选择保留现场。

## 验证什么

1. **带真实门控的环境启动**：两个 Avalon 实例健康（含 helper）、两个后端都被 Cascade 判为健康之后才允许客户端连入——正是避开"房间已可见、后端未健康"窗口所需的门控。
2. **主链路**：连大厅 → 拉清单 → 下载 → 哈希校验 → 物化 → 离房 → 热重载 → 重连 → `/goto` → 玩家在模组房内在位。
3. **自动 restore**（时延可配置），随后是快照断言：新装模组已禁用、快照键已全清、大厅无幽灵玩家、restore 后玩家回到应在的位置。
4. **敏感文案零误报**：只应在真实失败时出现的提示（未连大厅、重载失败、意外失败等）断言在正常流程中不出现。

## 通过、失败与排障

- 退出码 `0` = 全部检查通过；`1` = 有检查失败或前置缺失。前置缺失会明确指出缺什么后中止——绝不静默跳过。
- 端口、目录、二进制都可以用 `RWMI_*` 环境变量覆盖，避免与同机其它会话撞车。
- `RWMI_KEEP=1` 保留临时环境供排查（客户端态仍会还原）；摘要会指出客户端日志与各实例日志的位置。
